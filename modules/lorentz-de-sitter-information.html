2. Was ist dokumentiert?

Kovarianzbewusste Einparameter-Planung aus öffentlichen Pilotdaten, danach 16.384 neue unabhängige Wolken nach Quellenfixierung. Im Hauptvergleich senkt GLS234 den RMSE gegenüber C2 um 1,37%; das vorab gesetzte 10%-Ziel wird verfehlt. Bei schwacher Krümmung bleibt der approximative Datenbedarf hoch. Keine Freigabe von Krümmungsintervallen.

  • research/lorentz_de_sitter_information/RESULTS.md

    Hauptvergleich, approximative Budgets, negatives 10%-Gate und nächste Entscheidung.

  • research/lorentz_de_sitter_information/contract.json

    Öffentlicher Prüfvertrag vor dem frischen Test; Pilotplanung ist deskriptiv.

  • research/lorentz_de_sitter_information/results/summary.json

    Alle zwölf frischen Ergebniszeilen und gepaarter Bootstrapvergleich.

  • research/lorentz_de_sitter_information/results/hashes.json

    Prüfsummen aller Originalausgaben, einschliesslich vollständiger Kettenmerkmale und Relationshashes.

  • research/lorentz_de_sitter_information/VERIFICATION.json

    Vollständiger interner Replay und getrennte Kausalitäts-, Ketten-, Gewichts- und Momentprüfungen.

Evidenzberichte behalten ihre eigenen Prüfrevisionen. Ein Quellenpin belegt weder einen neuen Lauf noch unabhängige externe Begutachtung.

3. Wie lässt sich das prüfen?

Python 3.12, gepinnte NumPy-/SciPy-/Matplotlib-Versionen, vollständige Git-Historie. POSIX-Ziellauf begrenzt auf 600 Sekunden und 2 GiB.

In einem neuen Ordner ausführen; vorhandene Ausgabeordner nicht überschreiben. Voraussetzungen und paketbezogene Hinweise in der Originaldokumentation beachten.

git clone --branch main https://github.com/thomasmgfeller/x6-spectral-astrolabium.git x6-lorentz-de-sitter-information
cd x6-lorentz-de-sitter-information
git checkout --detach d6c9f3d9ddf975cdc6f0c2ce055c5becb1f7a2ee
python3 -m pip install -r research/lorentz_de_sitter_information/requirements.txt
python3 -B research/lorentz_de_sitter_information/verify.py

Erwartete Ausgabe

PASS_FULL_INFORMATION_REPLAY, 16.384 vollständig reproduzierte Punktwolken; interne Softwaregegenprüfung.
